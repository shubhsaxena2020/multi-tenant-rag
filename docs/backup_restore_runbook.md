# Backup & Restore Runbook

## Overview
This runbook documents the backup and restore procedures for the rag-service data layer, covering both PostgreSQL (tenant metadata, API keys) and Qdrant (vector collections).

---

## 1. PostgreSQL Backup & Restore

### 1.1 Logical Dump (pg_dump)

```bash
# Prerequisites
# - QDRANT__STORAGE__SNAPSHOTS_PATH must be set consistently
# - DB_URL must point to the target PostgreSQL instance

# Full database dump
pg_dump "$DB_URL" -Fc -f rag-service-backup-$(date +%Y%m%d-%H%M%S).dump

# Or via SQL for selective tables
pg_dump "$DB_URL" -t tenants -t tenant_keys -f rag-service-tenants-keys-$(date +%Y%m%d-%H%M%S).sql
```

### 1.2 Restore to Scratch DB

```bash
# Create a fresh scratch database
dropdb - "$DB_URL" 2>/dev/null || true
createdb "$DB_URL"

# Restore from dump
pg_restore -d "$DB_URL" rag-service-backup-20260904-075813.dump

# Verify row counts
psql "$DB_URL" -c "SELECT count(*) FROM tenants; SELECT count(*) FROM tenant_keys;"
```

### 1.3 Verification

```bash
# Confirm tenant count matches
psql "$DB_URL" -c "SELECT count(*) FROM tenants;"

# Confirm key count matches  
psql "$DB_URL" -c "SELECT count(*) FROM tenant_keys;"

# Verify key tiers are preserved
psql "$DB_URL" -c "SELECT kind, count(*) FROM tenant_keys GROUP BY kind;"
```

## 3. Combined Restore Workflow

### 3.1 Full System Restore Sequence

```bash
# Step 1: Restore PostgreSQL
pg_restore -d "$DB_URL" rag-service-backup-20260904-075813.dump

# Step 2: Verify tenant/key data
psql "$DB_URL" -c "SELECT count(*) FROM tenants; SELECT count(*) FROM tenant_keys;"

# Step 3: Restore Qdrant collections
# - Recreate collections on fresh Qdrant instance
# - Load vectors from backup
# - Verify vector counts match

# Step 4: Cross-validate
# - Confirm every tenant has matching Qdrant collection vectors
# - Verify API keys work against restored data
```

### 3.2 Rollback Plan

If restore fails mid-way:

1.  PostgreSQL: `dropdb "$DB_URL" && createdb "$DB_URL"` (fresh start)
2.  Qdrant: Re-deploy from previous Docker image/version tag
3.  Validate: Run health checks on both stacks before routing traffic

## 4. Prune Command (Snapshot Maintenance)

```bash
# List existing snapshots
ls ./qdrant_storage/snapshots/

# Prune snapshots older than 30 days (keep last 5)
find ./qdrant_storage/snapshots/ -name "*.snapshot" -mtime +30 | head -n +6 | xargs rm -f

# Or keep N most recent
ls -t ./qdrant_storage/snapshots/*.snapshot | tail -n +6 | xargs rm -f
```

### 4.1 Retention Policy

- **Keep**: Last 5 snapshots OR 30 days (whichever is longer)
- **Prune**: Anything older than 30 days beyond the 5 most recent
- **Verify**: `stat -c "%y %n" ./qdrant_storage/snapshots/*` before/after
